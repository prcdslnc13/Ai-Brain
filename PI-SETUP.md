# Using the Brain with pi (pi.dev)

[pi](https://pi.dev) ships without MCP support on purpose — MCP tool schemas are too
token-heavy for a minimal agent. That's fine: the Brain's primary interface is the `brain`
CLI, and pi has a shell tool. No extension required.

## Prerequisites

1. **The brain venv installed on this machine.** Run any of the setup paths
   (`brain-setup.py`, `setup-mac.sh`, `setup-linux.sh`, `setup-windows.ps1`) at least once so
   `mcp-server/.venv` exists and the `brain` console script is in it. The Claude-Code-specific
   parts of setup (hooks, skill) are harmless if you don't use Claude Code.
2. **The Obsidian vault synced down** to this machine.

## Sanity check

```bash
# macOS / Linux
BRAIN_VAULT=~/Documents/Vaults/Ai-Brain ~/src/Ai-Brain/mcp-server/.venv/bin/brain stats

# Windows (Git Bash) — or use the generated <config>\brain.cmd wrapper
BRAIN_VAULT="$USERPROFILE/Documents/Vaults/Ai-Brain" \
  /c/src/Ai-Brain/mcp-server/.venv/Scripts/brain.exe stats
```

One line of JSON with memory counts means everything works.

## Wire it into pi

Add the Brain snippet to your global or per-project `AGENTS.md` so the model knows the
commands and when to use them:

1. Copy `templates/AGENTS-brain.md` into (or append it to) your `AGENTS.md`.
2. Replace every `__BRAIN_CMD__` with the full invocation for this machine, e.g.
   - macOS/Linux: `BRAIN_VAULT="$HOME/Documents/Vaults/Ai-Brain" "$HOME/src/Ai-Brain/mcp-server/.venv/bin/brain"`
   - Windows: `C:/Users/<you>/.claude/brain.cmd` (the wrapper generated by setup, which bakes
     in `BRAIN_VAULT`), or an equivalent wrapper of your own.

One-liner for macOS/Linux:

```bash
sed "s|__BRAIN_CMD__|BRAIN_VAULT=\"$HOME/Documents/Vaults/Ai-Brain\" \"$HOME/src/Ai-Brain/mcp-server/.venv/bin/brain\"|g" \
  ~/src/Ai-Brain/templates/AGENTS-brain.md >> ~/.config/pi/AGENTS.md   # adjust target path to your pi setup
```

## Notes

- **No hooks in pi.** The Claude Code hooks (session preload, checkpoint-on-exit, stop gate)
  don't run here. The AGENTS snippet compensates by telling the model to recall the current
  project at session start and to checkpoint frequently. For a full preload bundle you can
  also run `mcp-server/.venv/bin/brain-prep --project <name>` and paste/pipe the output in.
- **Recall output is capped** the same as everywhere else (3 preview hits by default,
  ~300-char previews, hard total cap) — a local model can't blow its context on one recall.
- **If you'd rather keep MCP in pi**, the community
  [pi-mcp-adapter](https://github.com/nicobailon/pi-mcp-adapter) proxies MCP servers through
  one compact tool; point it at `python -m brain_mcp` with `BRAIN_VAULT` set. The plain CLI
  is simpler and cheaper, though.
